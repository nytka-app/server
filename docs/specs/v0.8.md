# Nytka v0.8 (moments and questions): mark a moment, hear it again, ask your history

Three features: a single tap on the pendant bookmarks the moment; a conversation's speech plays
back in the app; the Ask tab answers a question from your history with numbered sources. Pendant
settings (LED, microphone gain) and the firmware notice need firmware characteristics Nytka does not
read yet, and move to a later version.

## Done when

1. A single tap on the pendant stores a bookmark at the phone's time of the tap, also when the
   phone is offline; it reaches the server once, and the conversation around it shows it.
2. A double tap still toggles mute and never creates a bookmark.
3. A conversation whose speech audio is kept plays in the app; tapping a paragraph's time plays from
   that paragraph.
4. `POST /api/v1/ask` answers a question with text that cites numbered sources, and every number
   refers to a returned source (a conversation or a memory) the app can open.
5. No question, answer, transcript text or audio reaches a log.

## Bookmarks

**Server.** Table `bookmarks` (`0011_bookmarks.sql`): `id uuid` (made by the client), `at
timestamptz`, `note text null` (at most 200 characters), `source text` (`pendant` or `app`),
`created_at`. A bookmark references no conversation row: a conversation shows the bookmarks with
`at` from its `started_at` minus 30 s to its `ended_at` plus 30 s, so bookmarks follow conversation
merges and need no cascade (a bookmark outside every conversation stays listed on its own). Event
`bookmark.created` (webhooks) is published in the insert's transaction.

**App.** A `SingleTap` (event code 1) becomes a bookmark at the phone's clock when the notification
arrives. The app waits 700 ms before keeping it: a `DoubleTap` inside that time cancels it, so a
double tap never leaves a bookmark whatever order the firmware sends. A kept bookmark buzzes once
(100 ms), unlike mute (500 ms) and live (2 × 100 ms). Bookmarks go to a Room table and upload with
the chunk backoff (5 s to 5 min); the client `id` makes a retry a no-op. Taps while muted are kept.

The conversation screen marks a bookmark beside the nearest paragraph and can add a note; the list
shows a bookmark icon on conversations that have one.

**Limits.** The pendant sends taps only while connected; a tap while the phone is away is lost.

## Playback

**Server.** `GET /api/v1/conversations/{id}/audio` answers `audio/ogg` (Opus): the conversation's
`speech_audio` frames in capture order, packed into Ogg pages without re-encoding (codec 21 is Opus,
16 kHz, 20 ms frames; `OpusHead` input rate 16000, granule positions at 48 kHz). Pauses between
speech are not stored, so they are not played. Range requests are served. `404` when the
conversation has no speech audio (removed by `audio.retentionDays`, default 14, or imported).

`GET /api/v1/conversations/{id}/audio/index` answers `{ durationMs, runs: [{ offsetMs, startedAt,
endedAt }] }`: each stretch of continuous capture and where it starts in the stream, so the app maps
a capture time (a segment's `startedAt`) to a playback position. Both routes allow read tokens. The
writer (`OggOpusWriter` in `Nytka.Audio`) is tested by decoding its output back.

**App.** Media3 ExoPlayer with the OkHttp data source (the app's client and bearer token). The
conversation screen shows a play bar when `/audio/index` answers `200`; tapping a paragraph's time
seeks there. Playback stops when the screen closes.

## Ask

`POST /api/v1/ask { question }` (1 to 500 characters; read tokens allowed) answers
`{ answer, sources: [{ n, kind, id, conversationId, title, at, snippet }] }`. Two JSON-schema calls to
the configured model:

1. **Plan.** From the question and the local date and zone (`user.timeZone`), the model returns
   `{ queries: [up to 3 short keyword queries], from, to }` (local dates or null).
2. **Retrieve.** Each query runs through `SearchStore` (conversations and memories), limited to
   `from`..`to` when given. For a question, any word of a query may match (the terms are OR-ed, the
   ranking is the same); `/api/v1/search` keeps requiring every word. With dates and no query, the
   conversations in that range are taken, newest first. Hits merge by id, best score first, at most 8
   conversations and 10 memories. Each conversation contributes its title, summary, tasks, local date
   and the transcript window around its best-matching segment (labels as in v0.6), not the transcript
   from its start: the window grows line by line around that segment until its share of the total
   fits `MaxInputChars`, and short transcripts give back what they do not use. A conversation that
   matched only by title or summary gets the window from its start.
3. **Answer.** The model returns `{ answer, cited: [n] }`: `answer` uses `[n]` markers for the
   numbered sources it was given, and says so when they do not answer the question. The server drops
   markers that name no source and returns only the cited sources, renumbered from 1 in order of
   first mention.

`503` with a fixed message when no model is configured; `504` when a model call times out (`LlmException.TimedOut`);
`502` for any other model failure. The question and the answer are not stored.

**App.** The Ask tab (a placeholder today): a question field, the answer with `[n]` as links, the
sources below; a source opens its conversation (a memory opens its conversation when it has one).

## API

| Call | Scope | Effect |
|---|---|---|
| `POST /api/v1/bookmarks { id, at, note?, source }` | admin | `201`, or `200` when the id exists |
| `GET /api/v1/bookmarks?before&limit` | read | `{ items: [{ id, at, note, source, conversationId }], nextBefore }`, newest first, default 30, max 100 |
| `PATCH /api/v1/bookmarks/{id} { note }` | admin | sets or clears the note |
| `DELETE /api/v1/bookmarks/{id}` | admin | `204` |
| `GET /api/v1/conversations/{id}` | read | gains `bookmarks: [{ id, at, note }]`; list items gain `bookmarks` (a count) |
| `GET /api/v1/conversations/{id}/audio` | read | Ogg Opus speech |
| `GET /api/v1/conversations/{id}/audio/index` | read | playback map |
| `POST /api/v1/ask { question }` | read | answer with sources |

MCP gains `list_bookmarks` and `ask`.

## Not in this version

- LED brightness, microphone gain, the firmware notice: need the pendant's settings and DFU
  characteristics mapped first.
- Streaming answers, follow-up questions, vector search (after 1.0).
- Playing the pauses: they are never stored.
